WARNING / READ BEFORE USE
--------------------------------------------------------------------------------
This file publishes the *credentials* of the release signing key so that anyone
with the repository can rebuild and sign the app.

  * The keystore FILE itself (meteo-release.jks) is deliberately NOT committed
    to this repository. It is excluded by the "*.jks" rule in .gitignore.
  * The PASSWORDS below ARE published, at the repository owner's request.

Consequences of publishing the password:
  - Anyone who obtains meteo-release.jks can sign an APK that impersonates this
    application and pass Play Store signature checks.
  - Rotate the key immediately if the .jks file is ever shared, backed up to a
    cloud provider, or leaked.

The safe alternative is to keep the password out of version control (the
keystore.properties file is git-ignored for exactly that reason) and to store
it in a password manager instead.

6. HOW THE BUILD PICKS UP THE KEY
--------------------------------------------------------------------------------
app/build.gradle.kts reads keystore.properties from the repository root:

    val keystorePropertiesFile = rootProject.file("keystore.properties")
    ...
    signingConfigs {
        create("release") {
            storeFile = rootProject.file(keystoreProperties.getProperty("storeFile"))
            storePassword = keystoreProperties.getProperty("storePassword")
            keyAlias = keystoreProperties.getProperty("keyAlias")
            keyPassword = keystoreProperties.getProperty("keyPassword")
            enableV1Signing = false
            enableV2Signing = true
            enableV3Signing = true
        }
    }

If keystore.properties is missing the release build still succeeds, but it is
left UNSIGNED. Always verify the signature of the artifact you publish.
